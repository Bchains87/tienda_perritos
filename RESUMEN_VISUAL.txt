│  └─ Queries: MySQL ? → PostgreSQL $1, $2, $3                             │
│                                                                             │

┌─────────────────────────────────────────────────────────────────────────────┐
│ PROBLEMA 3: PROXY INVERSO NO CONFIGURADO (ALTO) 🟠                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ANTES: Frontend → /api/productos → ❌ (sin proxy)                        │
│  └─ default.conf: proxy_pass http://IP_PRIVADA_BACKEND:3001 (comentado)  │
│                                                                             │
│  DESPUÉS: Frontend → /api/productos → Nginx → Backend ✅                  │
│  ├─ default.conf: proxy_pass http://tienda-backend:3001                  │
│  └─ Headers: X-Real-IP, X-Forwarded-For, X-Forwarded-Proto               │
│                                                                             │
│  FLUJO CORRECTO:                                                           │
│  1. Browser hace fetch("/api/productos")                                  │
│  2. Nginx intercepta /api/ y lo redirige a http://tienda-backend:3001   │
│  3. Backend responde y Nginx devuelve al browser                         │
│                                                                             │
│  IMPACTO: Frontend no podía acceder a datos, tabla CRUD no funcionaba    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ PROBLEMA 4: CREDENCIALES EXPUESTAS (ALTO) 🟠                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ANTES: Secrets en el código ❌ (INSEGURO)                                │
│  deploy.yml, línea 69:                                                     │
│  -e DB_PASSWORD=alumno123 -e DB_USER=alumno                              │
│  ↑ VISIBLE en GitHub para cualquiera                                      │
│                                                                             │
│  DESPUÉS: Secrets en GitHub ✅ (SEGURO)                                   │
│  deploy.yml, línea 71-74:                                                │
│  -e DB_USER=${{ secrets.DB_USER }}                                       │
│  -e DB_PASSWORD=${{ secrets.DB_PASSWORD }}                               │
│  -e DB_NAME=${{ secrets.DB_NAME }}                                       │
│  -e DB_PORT=${{ secrets.DB_PORT }}                                       │
│                                                                             │
│  VENTAJAS:                                                                 │
│  • Contraseñas ocultas en GitHub (*** en logs)                           │
│  • Acceso controlado a secrets                                            │
│  • Fácil rotación de credenciales                                        │
│                                                                             │
│  IMPACTO: Riesgo de seguridad crítico eliminado                          │
│                                                                             │
